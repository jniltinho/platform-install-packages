## Revisão (independente, estática)

- **Correto:**
  - O nonce e a phase são validados antes do `require` de `kApcConf`.
  - Comparei os resultados esperados em `client.py:81-90` com o código real de `kApcConf.php`/`kBaseConfCache.php`: `storeKey` cai em `return null` quando não há apc, e `store` em `return false`. Os valores batem.
  - O `$map` é passado por valor, então o `newMap` do replace recebe a própria `CONF_CACHE_KEY`.
  - `exact()` distingue bool de int.
  - Com um único worker prefork (`MaxRequestWorkers 1`) e o PID invariante, fica comprovado que todos os pedidos foram atendidos pelo mesmo worker.
- **Ressalvas (nenhuma é defeito):**
  1. No modo original, as fases de persistência não testam persistência, porque tudo retorna null. Esse é o comportamento esperado para esse modo.
  2. A chave de versão (`CONF_CACHE_VERSION_KEY`) é global e não isolada por nonce. Não afeta nada aqui porque cada run sobe um Apache novo, mas o fixture não serve para vários runs no mesmo processo.
  3. O `SOURCE_HASHES` fica só no cliente e a comparação é feita depois da resposta. Ainda assim o fixture falha fechado.
  4. A limitação de SSH está confirmada: `/tmp/kaltura-php74-ssh.conf` usa `StrictHostKeyChecking no` e `UserKnownHostsFile /dev/null`, então a chave do host não é fixada.
